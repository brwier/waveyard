## 1. Purpose, goals, non-goals

### 1.1 Purpose

A lightweight, open-source electromagnetic simulator for photonic integrated circuit (PIC) components that:

1. takes real layouts (GDSII/OASIS via gdsfactory) plus a process layer stack and produces wavelength-resolved S-parameters usable in circuit simulation;
2. runs on the CPU and on consumer GPUs from both AMD and NVIDIA;
3. is small enough to be understood end to end, and structured so that its capabilities grow (frequency domain, inverse design, fp64) without rewrites.

It serves two purposes with equal weight: a working design tool for the owner's own PIC work, and a public demonstration of photonics design-automation competence.

### 1.2 Goals (v1)

- G1. GDS + LayerStack → 3D permittivity grid with subpixel averaging, in one call.
- G2. 3D FDTD (2D as the degenerate case) with CPML boundaries, Lorentz-dispersive materials, eigenmode sources, and DFT mode monitors.
- G3. Full-vector finite-difference waveguide mode solver (n_eff, n_g, fields).
- G4. S-parameter matrix vs wavelength from a single run per input port, exported as xarray, Touchstone, and a sax-compatible model.
- G5. One functional stepper that runs on NumPy (CPU) and PyTorch (CPU, CUDA, ROCm) via the Python array API.
- G6. Validated against analytic cases and against Meep on a directional coupler.
- G7. Declarative, serializable object model (pydantic) that a user can inspect, hash, and plot before running.

### 1.3 Non-goals (v1)

- Nonuniform or conformal meshes; anisotropic subpixel tensors.
- Symmetry planes, periodic boundaries, Bloch boundaries.
- Autodiff/adjoint gradients (v1.2), multi-GPU (v2), fp64 field arrays (v1.2 option).
- Nonlinear, active, thermal, or carrier physics (roadmap; the ADE machinery is designed to admit them).
- EME, FDFD, BPM (v2).
- A GUI. Plots are matplotlib; interactive 3D is out of scope.
- Windows as a supported platform. Linux is the development and support target; the v1.1 wgpu backend will also run on Windows but is untested there.

## 2. Users and use cases

| User | Use case | What they touch |
|---|---|---|
| Owner as designer | S-parameters of a coupler / MMI / ring drawn in gdsfactory, fed into sax | `Simulation.from_component`, `write_sparameters`, plots |
| Reviewer / hiring manager | Read code and notebooks, judge architecture and validation rigor | Object model, plan schema, tests, Meep comparison notebook |
| gdsfactory user | Drop-in alternative to gplugins' Meep/Tidy3D paths | `write_sparameters` with the gplugins argument conventions |
| Future owner | Add a backend (JAX, wgpu), add physics (EME, adjoint) | Backend protocol, plan schema, functional stepper rules |

Primary workflow (must be one screen of code):

```python
import gdsfactory as gf
import picfdtd as pf

c = gf.components.coupler(gap=0.2, length=10)
sim = pf.Simulation.from_component(
    c, layer_stack=pf.layer_stacks.SOI220, materials=pf.materials.SOI,
    wavelengths=pf.wavelengths(1.5, 1.6, 21), cell_size=0.02,
)
sim.plot_eps(z=0.11)                      # inspect before running
data = pf.run(sim, backend="torch", device="rocm")
S = data.sparameters()                    # xarray: (wavelength, port_in, port_out)
S.to_touchstone("coupler.s4p")
```

## 5. Numerical methods

All equations use normalized units (D11): c = ε₀ = μ₀ = η₀ = 1; length in µm; time in µm/c (1 unit = 3.3356 fs); angular frequency ω = 2π/λ with λ in µm; frequency f = 1/λ. Conversion to SI happens only at the API boundary.

Time-harmonic convention: e^{+jωt}. Fourier transform F(ω) = ∫ f(t) e^{−jωt} dt.

### 5.1 Yee grid

Uniform cells (Δx, Δy, Δz). Field locations (integer indices i, j, k):

| Field | Position |
|---|---|
| Ex | (i+½, j, k) |
| Ey | (i, j+½, k) |
| Ez | (i, j, k+½) |
| Hx | (i, j+½, k+½) |
| Hy | (i+½, j, k+½) |
| Hz | (i+½, j+½, k) |

Array shapes: all six arrays are allocated as (nx, ny, nz) with the half-cell offset implied by the field type. E at integer time steps n, H at n+½.

### 5.2 Update equations (non-dispersive, with conductivity)

Maxwell in normalized units with relative permittivity ε (denoted ε_∞ for dispersive media), conductivity σ, and impressed current J:

```
∂H/∂t = −∇×E
ε_∞ ∂E/∂t = ∇×H − σ E − J − Σ_p ∂P_p/∂t
```

Leapfrog:

```
H^{n+½} = H^{n−½} − Δt (∇×E)^n − Δt M^{n}          # M: magnetic source current (mode source)
E^{n+1}  = ca · E^n + cb · [ (∇×H)^{n+½} − J^{n+½} − ΔP^{n+1}/Δt ]
```

with semi-implicit conductivity:

```
ca = (ε_∞ − σΔt/2) / (ε_∞ + σΔt/2)
cb =  Δt              / (ε_∞ + σΔt/2)
```

`ca`, `cb` are per-cell fp32 arrays per E component (from subpixel-averaged ε_∞ and σ). Curls are the standard second-order central differences on the staggered grid.

### 5.3 Dispersive materials: Lorentz ADE

Relative permittivity model (e^{+jωt} convention):

```
ε(ω) = ε_∞ + Σ_p  Δε_p ω_p² / (ω_p² + 2jδ_p ω − ω²)  −  jσ/ω
```

Each pole p carries a polarization P_p obeying

```
d²P_p/dt² + 2δ_p dP_p/dt + ω_p² P_p = Δε_p ω_p² E
```

Central-difference (explicit) update, evaluated before the E update:

```
P_p^{n+1} = C1_p P_p^n + C2_p P_p^{n−1} + C3_p E^n

C1_p = (2 − ω_p²Δt²) / (1 + δ_pΔt)
C2_p = −(1 − δ_pΔt)  / (1 + δ_pΔt)
C3_p =  Δε_p ω_p² Δt² / (1 + δ_pΔt)
```

Then ΔP^{n+1} = Σ_p (P_p^{n+1} − P_p^n) enters the E update of §5.2. Because P^{n+1} depends only on E^n and earlier, the scheme is explicit. State per pole: two arrays per component (P^n, P^{n−1}).

Subpixel handling for dispersive media (§5.6): C3_p is stored as an array equal to f_m · C3_p,m where f_m is the cell's volume fraction of dispersive material m; ε_∞ is volume-averaged. A cell containing two different dispersive materials is assigned both pole sets (union), each scaled by its fraction. v1 caps the total at 2 poles per cell.

Storage (SHOULD): P arrays cover only the axis-aligned bounding box of all cells with f_m > 0 for that pole, plus one cell of padding. For a 220 nm Si layer in a 3 µm-tall domain this is roughly a 10× memory reduction.

### 5.4 Time step and stability

```
Δt = S / sqrt(1/Δx² + 1/Δy² + 1/Δz²),   S = 0.99 default (2D: drop the z term)
```

`Simulation.validate()` MUST additionally check, for every Lorentz pole, ω_p Δt ≤ 1.0 (conservative; the central-difference oscillator limit is 2) and δ_p Δt ≤ 1.0, and refuse to run otherwise with a message suggesting a smaller cell or a different fit. A UV pole for silicon (λ_p ≈ 0.3 µm, ω_p ≈ 21 µm⁻¹) at Δ = 20 nm gives ω_pΔt ≈ 0.24: comfortably stable.

### 5.5 CPML (Roden & Gedney)

Stretched coordinate per axis w ∈ {x, y, z}: s_w = κ_w + σ_w / (α_w + jω). Each spatial derivative inside the PML slab is replaced by (1/κ_w) ∂_w + ψ, with the auxiliary ψ arrays updated as

```
ψ^{n+½} = b_w ψ^{n−½} + c_w (∂_w field)^n
b_w = exp[−(σ_w/κ_w + α_w) Δt]
c_w = σ_w (b_w − 1) / (σ_w κ_w + κ_w² α_w)
```

Coefficients are 1D profiles along the PML depth ρ ∈ [0, d], evaluated at both integer and half-integer positions:

```
σ_w(ρ) = σ_max (ρ/d)^m
κ_w(ρ) = 1 + (κ_max − 1)(ρ/d)^m
α_w(ρ) = α_max (1 − ρ/d)^{m_a}
σ_max  = 0.8 (m + 1) / (Δ_w sqrt(ε_r,adjacent))     # η₀ = 1
```

Defaults: d = 12 cells, m = 3, m_a = 1, κ_max = 1, α_max = 0.05 (normalized units). These are starting values; M3 tunes them against the reflection tests in §11.2 and freezes the defaults. ε_r,adjacent is the ε_∞ of the medium touching that face; structures (waveguides, cladding) MUST extend through the PML unchanged, which the port-extension step in §6 guarantees.

ψ arrays exist only inside PML slabs: 12 arrays total (two curl terms × three axes × two faces), each sized to its slab.

### 5.6 Subpixel averaging (volume fraction)

For each E-component grid, each cell is the Δx×Δy×Δz box centered on that component's location. The geometry engine (§6) computes, per cell and per material, the volume fraction f_m by supersampling the in-plane polygon masks (N_ss × N_ss, default 4) and exact interval overlap in z (layers are z-extruded). Effective parameters:

```
ε_∞,eff = Σ_m f_m ε_∞,m       σ_eff = Σ_m f_m σ_m       C3_p,eff = f_m C3_p,m
```

PEC wins any cell it touches (f_PEC > 0 → E component pinned to zero). v2 replaces the scalar average with the anisotropic tensor of Farjadpour et al. (2006) for non-dispersive interfaces.

### 5.7 Sources

**Time waveform** (all sources):

```
g(t) = exp(−(t − t₀)² / (2τ²)) · cos(ω₀ (t − t₀)),   τ = 1/(2π f_width),   t₀ = 5τ
```

`GaussianPulse(wavelength0, fwidth)` with fwidth in frequency units (1/µm). Default fwidth covers 1.45–1.65 µm when the requested band is 1.5–1.6 µm. The waveform is tabulated once, g[n] = g(nΔt) for E-side currents and g((n+½)Δt) for H-side currents.

**Unidirectional mode source.** On the source plane with unit normal n̂ (axis-aligned) the solver injects equivalent surface currents built from the mode fields (E_m, H_m) at the center wavelength:

```
J_s = +n̂ × H_m      (added to the E update on the plane, as −J in §5.2)
M_s = −n̂ × E_m      (added to the H update half a cell toward −n̂, as −M in §5.2)
```

with the mode normalized to unit power (§5.9) and the E- and H-side waveforms offset by Δt/2 and by the half-cell spatial offset so that the radiated fields add in the +n̂ direction and cancel in −n̂. Direction "−" flips the sign of M_s. Acceptance: backward-radiated power ≤ −30 dB relative to forward (§11.3). The mode profile is frequency-independent within the pulse (as in Tidy3D and Meep); this is adequate for ≤ 10 % bandwidth and is documented as a limitation.

**Point dipole.** J or M delta at one cell, polarization along x, y, or z.

### 5.8 Monitors

**DFT accumulation.** For each monitor with frequencies f_k, k = 1..K, and each stored component:

```
F̂_k += F^n · exp(−j ω_k t_n) · Δt      (E at t_n = nΔt; H at t_n = (n+½)Δt)
```

Accumulators are stored as separate real and imaginary fp32 arrays (portable to WGSL); fp64 accumulation is an option (`dtype_accum="float64"`) for long runs. Cos/sin tables are precomputed per step in the plan (K × n_steps fp32, small).

**Mode monitor.** Stores tangential Ê and Ĥ on a plane. Post-processing interpolates the staggered components to a common set of plane locations (linear operations commute with the DFT) and computes modal amplitudes (§5.10).

**Field monitor.** Stores selected components on a plane or in a box; returned as xarray with coordinates in µm.

**Time monitor.** Stores one component at one point for every step (for decay and debugging); also drives auto-shutoff (SHOULD): stop when the running maximum of |E| over the last 2t₀ falls below 10⁻⁵ of the global maximum.

### 5.9 Mode solver

Full-vector finite-difference eigenmode solver on the port cross-section using the transverse-H formulation of Fallahkhair, Li & Murphy (2008), which handles permittivity discontinuities on a Yee-consistent grid.

- Grid: the FDTD cross-section grid (same Δ), so mode fields map directly onto Yee locations without interpolation.
- Operator: sparse (scipy.sparse), fp64. Generalized eigenproblem A h = β² h.
- Solve: `scipy.sparse.linalg.eigs` with shift-invert at σ = (k₀ n_max)², `num_modes` requested, sorted by descending n_eff.
- Boundary: PEC box; the port plane MUST extend ≥ `port_margin` (default 1.0 µm) beyond the core on every side. PML in v1.1.
- Outputs: n_eff (complex if lossy media), E and H fields on the cross-section, TE fraction (∫|E_t,major|² / ∫|E_t|²), unit-power normalization ½ Re ∫ (E_m × H_m*)·n̂ dA = 1.
- Group index: n_g = n_eff − λ dn_eff/dλ by central difference at λ(1 ± 0.005); three solves.
- Materials in the mode solver use ε(ω) evaluated at the requested wavelength from the same Lorentz model (frequency-domain evaluation), so mode-solver and FDTD material data are consistent by construction.

### 5.10 S-parameter extraction

For a mode monitor on port q with mode m normalized to unit power, the forward (+n̂_out, i.e. leaving the device) and backward amplitudes at frequency f_k are

```
a⁺ = ¼ ∫ ( Ê × H_m* + E_m* × Ĥ ) · n̂ dA
a⁻ = ¼ ∫ ( Ê × H_m* − E_m* × Ĥ ) · n̂ dA
```

Sign conventions are fixed in M4 by the straight-waveguide test (|S21| → 1, S11 → 0).

With one unidirectional mode source on port i and a mode monitor on every port (the port-i monitor placed one cell on the device side of the source plane):

```
S_ii(f) = a⁻_i(f) / a⁺_i(f)          # reflection: backward over incident
S_ji(f) = a⁺_j(f) / a⁺_i(f)          # transmission into port j's outgoing direction
```

Because the source is unidirectional, a⁺_i is the incident amplitude and no reference run is required. An N-port device requires N runs; `run_sparameters` performs them and assembles the full matrix. Reciprocity is available as an option to halve the runs (`assume_reciprocal=True`). Phase is referenced to the monitor planes; `Port.reference_shift` (µm) applies exp(±jβL) corrections so phases refer to the component's port positions.

Multi-mode ports produce block S-matrices indexed by (port, mode).

### 5.11 Two-dimensional mode

`Simulation(dims=2)` sets nz = 1, drops ∂/∂z and the z-PML, and decouples the polarizations: `polarization="te"` evolves (Ex, Ey, Hz), `"tm"` evolves (Ez, Hx, Hy). The permittivity map is 2D; in v1 the user supplies it through `EffectiveIndexMap`, which assigns an effective index per LayerStack region (core, slab, cladding). v1.1 computes those indices automatically from the 1D slab modes at the center wavelength. The 2D mode solver reduces to the 1D slab problem on the port line.

### 5.12 Symmetry (v1.1)

Mirror symmetry planes through the domain center with ±1 phase, halving or quartering the grid. Deferred because ports and sources must be symmetric-aware.

## 6. Geometry pipeline (GDS → permittivity)

Inputs: a gdsfactory `Component` (or a `.gds`/`.oas` path, which is read into one), a gdsfactory `LayerStack`, a `materials` dict mapping LayerStack material names to `Medium` objects, and grid/domain settings.

Steps:

1. **Derived layers.** `layer_stack.get_component_with_derived_layers(component)` resolves boolean layer definitions (etch layers, slabs) into concrete polygons on a scratch component.
2. **Port extension.** Every port is extended straight outward by `port_extension` (default 1.5 µm) so that the source plane, port monitor, and PML all sit in uniform waveguide. The extension length MUST satisfy `port_extension ≥ pml_thickness + 2·source_monitor_gap + 0.5 µm`.
3. **Polygon extraction.** Per LayerLevel, flatten the hierarchy and take the boolean union with gdstk (`gdstk.boolean(..., "or")`). gdstk returns hole-free polygons (holes become keyholes), which the rasterizer relies on.
4. **Extrusion.** Each LayerLevel becomes a z-interval [zmin, zmin + thickness]. A nonzero sidewall angle is applied as a z-dependent polygon offset (gdstk `offset`), sampled at every z-cell boundary. `mesh_order` resolves overlaps: the lowest mesh_order wins in a cell.
5. **Domain.** Simulation box = component bounding box (after extension) expanded by `port_margin` laterally, with z from `z_min`/`z_max` (defaults from the LayerStack: box bottom − 1.0 µm to cladding top + 1.0 µm), plus PML on all faces. Background medium = cladding (default SiO₂). Substrate below the BOX is a `Box` structure (default Si) if within the domain.
6. **Rasterization.** For each of the three E-component grids and each z-slice of each layer: draw the layer's polygons on a supersampled 2D grid (N_ss = 4 per axis) with `cv2.fillPoly`, block-average to fill fractions, multiply by the exact z-overlap fraction, and accumulate into the per-material fraction array f_m. Fraction arrays sum to ≤ 1; the remainder is background.
7. **Coefficient synthesis.** From f_m and the media: `ca`, `cb` (3 arrays each), per-pole `C3` arrays on their bounding boxes, PEC masks. This is the `EpsGrid`.
8. **Ports.** Each gdsfactory port (center, width, orientation, layer) becomes a `Port` with an axis-aligned plane: normal along the orientation, transverse extent = width + 2·port_margin, z extent = full domain minus PML. Non-Manhattan port orientations are rejected in v1.
9. **Caching.** `EpsGrid` is cached on disk keyed by a hash of (GDS bytes, LayerStack JSON, materials JSON, grid, domain). Rasterization of a 50 M-cell grid is expected to take 10–60 s in NumPy; caching makes parameter sweeps of sources/monitors free.

The pipeline also accepts raw polygons (`Polygon2D`) without gdsfactory, so gdsfactory is an optional dependency (`picfdtd[gds]`).

Diagnostics: `Simulation.plot_eps(x=…|y=…|z=…)` renders ε_∞ slices; `EpsGrid.to_klayout_xs()` MAY export a cross-section for comparison with KLayout's 2.5D viewer.

## 7. Materials library and fitting

`Medium` hierarchy (§8.2). Shipped materials (`picfdtd.materials`), each with the dataset citation and fit residual recorded in its docstring:

| Name | Source data | Default model over 1.2–1.7 µm |
|---|---|---|
| `Si` | Li (1980) / Salzberg & Villa | 1 Lorentz pole, ε_∞ ≈ 7.98; fit error |Δn| < 2e-4 |
| `SiO2` | Malitson (1965) | 1 Lorentz pole |
| `Si3N4` | Luke et al. (2015) | 1 Lorentz pole |
| `Ge` | Nunley et al. (2016) | 2 poles + σ (absorbing) |
| `Air` | — | n = 1, non-dispersive |
| `SOI` | dict | `{"si": Si, "sio2": SiO2, "sin": Si3N4, "ge": Ge}` matching gdsfactory's generic LayerStack material names |

Fitting tool: `LorentzMedium.from_nk(wavelengths, n, k, n_poles=1, wl_range=(1.2, 1.7))` runs `scipy.optimize.least_squares` on the complex ε(ω) residual with bounds Δε_p ≥ 0, δ_p ≥ 0, ε_∞ ≥ 1 (passivity), and reports max |Δn| and |Δk| over the range. Users can also pass refractiveindex.info YAML files. Constant-index media remain available (`Dielectric(n=3.48)`) for speed or for Meep-matched comparisons.

Dependency rule: `model` imports nothing from `plan` or `backends`; `plan` imports `model` and `geometry`; `backends` import only `plan` (never `model`). This is what keeps the plan the single backend contract.

### 8.2 Object model

All classes are pydantic v2 `BaseModel` with `frozen=True`, `extra="forbid"`, explicit units in field descriptions (µm for lengths, 1/µm for frequencies), a stable `hash` (SHA-256 of canonical JSON), and `to_json`/`from_json`.

**Media**

```python
class Medium(BaseModel):            name: str | None
class Dielectric(Medium):           n: float ≥ 1; sigma: float ≥ 0 = 0
class LorentzPole(BaseModel):       delta_eps: float ≥ 0; f0: float > 0; delta: float ≥ 0   # f0 in 1/µm
class LorentzMedium(Medium):        eps_inf: float ≥ 1; poles: list[LorentzPole] (≤ 2); sigma: float ≥ 0 = 0
                                    def eps(self, wavelength) -> complex
                                    @classmethod from_nk(...)
```

```python

    structures: list[Structure]; background: Medium
    sources: list[ModeSource | PointDipole]
```

### 8.3 Discretization plan

`Plan` is a plain dataclass of NumPy arrays and scalars; it is the entire contract between physics and backends. Nothing downstream computes a physical coefficient.

```
Plan
  grid:      nx, ny, nz, dx, dy, dz, dt, n_steps, dims
  coeffs:    ca[3], cb[3]                       fp32 (nx,ny,nz) each; PEC folded in (ca=cb=0)
  ade:       list[PoleBlock]                    each: slices (bbox), C1, C2 scalars, C3 array (bbox), component
  cpml:      per axis: b_e, c_e, kappa_e, b_h, c_h, kappa_h  (1D fp32); thickness; psi shapes
  sources:   list[SourceBlock]                  slices, J/M spatial profile arrays (fp32), waveform tables g_e[n], g_h[n]
  monitors:  list[MonitorBlock]                 kind, slices, components, omegas (fp64), cos/sin tables or recurrence params
  meta:      simulation hash, units, version
```

`plan.serialize.save(plan, path)` writes an `.npz` + JSON header; backends can be tested from saved plans without the model layer. `Plan.memory_bytes(backend)` supports `Simulation.estimate()`.

### 8.4 Backend protocol and functional-stepper rules

```python
class Backend(Protocol):
    name: str
    capabilities: frozenset[str]      # e.g. {"dims3", "dims2", "lorentz", "cpml", "mode_source", "dft", "time_monitor", "fp64_accum"}
    def init(self, plan: Plan, *, device: str | None = None, dtype: str = "float32") -> State
    def run(self, state: State, n_steps: int, *, progress: Callable | None = None) -> State
    def readout(self, state: State) -> RawResults        # NumPy arrays, monitor-keyed
```

`Simulation.validate_physics()` MUST check that every feature used is in the chosen backend's capabilities, so a backend is allowed to lag (wgpu in particular).

Rules for the shared stepper (`backends/arrayapi/stepper.py`), written so a JAX backend is an add, not a rewrite:

1. `State` is a frozen dataclass of arrays: E[3], H[3], P per pole, psi per PML slab, DFT accumulators (re/im), time-monitor buffers, step counter.
2. Every update is a pure function `f(state, plan_arrays, n) -> new arrays`; no in-place mutation of inputs. Out-of-place ops only.
3. All array operations go through `xp = array_api_compat.array_namespace(...)`; no `np.` or `torch.` calls in `stepper.py`.
4. The time loop lives in `loop.py` and is backend-specific (`for` in NumPy/PyTorch; would be `lax.fori_loop` in JAX). `torch_backend` MAY wrap one full step in `torch.compile`.
5. Monitors accumulate into state; no callbacks with side effects inside the step.
6. Complex quantities are stored as (re, im) pairs, not complex dtypes.
7. One helper owns dtype/device placement (`to_backend(array, device, dtype)`); nothing else touches devices.
8. Step order per iteration n: `update_h` (uses E^n) → `inject_M` → `update_psi_e` → `update_ade` (P^{n+1}) → `update_e` → `inject_J` → `update_psi_h` → `accumulate_dft` → `record_time`.

Cost of the functional style in eager PyTorch is ~1.2–1.5× allocation overhead; `torch.compile` recovers it (§10).

### 8.5 Backends

| Backend | Devices | Status | Notes |
|---|---|---|---|
| `numpy` | CPU | v1 MUST | Reference/oracle; correctness over speed |
| `torch` | CPU, CUDA, ROCm | v1 MUST | Same stepper; `device="cpu"|"cuda"|"rocm"` (`rocm` maps to torch `cuda` device on ROCm builds); optional `compile=True` |
| `wgpu` | Vulkan/DX12/Metal, any vendor | v1.1 | WGSL kernels (Appendix C); reuses plan tables and parity tests; capabilities may exclude `fp64_accum` |
| `jax` | CPU, CUDA, ROCm (plugin) | v2 MAY | `lax.fori_loop`, `custom_vjp` adjoint |

Backend selection: `run(sim, backend="auto")` picks `torch` on a GPU if available, else `torch` CPU if installed, else `numpy`.

## 9. API examples

**Straight waveguide, object model, no gdsfactory**

```python
import picfdtd as pf

si, sio2 = pf.materials.Si, pf.materials.SiO2
wg = pf.Structure(pf.Polygon2D([(-6, -0.25), (6, -0.25), (6, 0.25), (-6, 0.25)], z_min=0, z_max=0.22), medium=si)
pulse = pf.GaussianPulse(wavelength0=1.55, fwidth=pf.fwidth_from_range(1.45, 1.65))
wls = pf.wavelengths(1.5, 1.6, 21)
p1 = pf.Port("o1", center=(-4.5, 0, 0.11), size=(0, 2.5, 2.5), normal_axis="x", direction="-")
p2 = pf.Port("o2", center=( 4.5, 0, 0.11), size=(0, 2.5, 2.5), normal_axis="x", direction="+")

sim = pf.Simulation(
    center=(0, 0, 0.11), size=(12, 4, 3), background=sio2, structures=[wg],
    sources=[p1.to_source(pulse)], monitors=[p1.to_monitor(wls), p2.to_monitor(wls)],
    grid=pf.GridSpec(cell_size=0.02), boundary=pf.Boundary.pml_all(12), ports=[p1, p2],
)
print(sim.estimate())            # cells, memory per backend, steps
data = pf.run(sim, backend="torch", device="rocm")
S = data.sparameters("o1")
assert abs(S.sel(port_in="o1", port_out="o2")).min() > 0.995
```

## 10. Performance requirements and sizing

### 10.1 Reference problem "DC-A"

Directional coupler on 220 nm SOI, domain 24 × 6 × 3 µm, Δ = 20 nm → 1200 × 300 × 150 = 54 M cells; Lorentz Si in a 0.26 µm-tall ADE box; 4 ports; 21 wavelengths 1.5–1.6 µm; run_time ≈ 250 µm/c → ~22 k steps.

Memory (fp32): fields 6 + coefficients 6 = 12 full arrays × 216 MB ≈ 2.6 GB; ADE box ≈ 0.2 GB; CPML ψ ≈ 0.1 GB; DFT accumulators ≈ 0.1 GB. **≈ 3.0 GB**, fitting a 16 GB RX 9070 with room for `torch.compile` workspace.

Traffic: ~100 B per cell per step for fused kernels ⇒ 5.4 GB/step ⇒ 8 ms/step at 640 GB/s. Eager out-of-place PyTorch makes ~30 full-array passes per step (≈ 13 GB) plus launch overhead.

### 10.2 Targets (v1.0 unless noted)

| Backend / device | Target throughput (cell·steps/s) | DC-A wall time |
|---|---|---|
| `numpy`, one core | ≥ 40 M | hours (reference only) |
| `torch` CPU, 8 cores | ≥ 150 M | ≤ 2.5 h |
| `torch` ROCm RX 9070 XT, eager | ≥ 1.5 G | ≤ 15 min |
| `torch` ROCm, `compile=True` | ≥ 3 G | ≤ 7 min |
| `wgpu` RX 9070 XT (v1.1) | ≥ 5 G | ≤ 4 min |

Also required: mode solve for a 3 × 3 µm cross-section at Δ = 20 nm (22.5 k unknowns × 2) in ≤ 5 s; GDS → EpsGrid for DC-A in ≤ 60 s uncached, ≤ 1 s cached; `Simulation.estimate()` within ±30 % of measured memory.

A benchmark script (`benchmarks/run.py`) records cell·steps/s, peak memory, and hardware for each backend and appends to `benchmarks/results.jsonl`.

## 11. Validation and testing

Test tiers (pytest markers): `unit`, `analytic`, `integration`, `parity`, `meep`, `gpu`, `slow`, `bench`.

### 11.1 Unit

- Object model: validation errors on bad units, overlapping-zero plane sizes, sources outside the domain, monitors inside PML, non-Manhattan ports.
- Plan: coefficient arrays match hand-computed values for uniform media; PML profiles monotone; waveform tables have the intended spectrum (FFT check).
- Rasterizer (hypothesis): fill fractions in [0, 1], sum ≤ 1, exact for axis-aligned rectangles on grid, converge as N_ss grows for rotated rectangles; keyhole polygons from gdstk handled.
- Materials: `from_nk` fits reproduce tabulated n within stated residual; `eps(λ)` matches the ADE steady-state response (single-cell oscillator test).

### 11.2 Analytic (NumPy backend; torch CPU in the same parametrization)

| Test | Setup | Acceptance |
|---|---|---|
| A1 Pulse propagation | 1D (ny = nz = 1) free space | group velocity = 1 within numerical-dispersion prediction at Δ = λ/20 |
| A2 Fresnel | 1D, half-space n = 2 and Lorentz-fit Si | R, T within 1 % of analytic at 21 wavelengths |
| A3 Lorentz slab | 1D slab 1 µm, 1-pole medium | complex transmission vs transfer-matrix with the same ε(ω): |ΔT| < 0.01, phase < 2° |
| A4 PML normal | 1D and 3D plane wave into PML | reflected power ≤ −40 dB across band |
| A5 PML oblique | 2D at 45° | ≤ −30 dB |
| A6 Energy | closed PEC box, lossless dielectric inclusion, dipole then off | stored energy constant to 1e-3 (fp32) over 5000 steps |
| A7 Convergence | DC-A |S21| at Δ = 40/30/20/15 nm | monotone, observed order ≥ 1.5 |
| A8 Mode source directivity | straight waveguide, monitors both sides | backward/forward ≤ −30 dB |

### 11.3 Mode solver

- M1 Symmetric slab: TE/TM n_eff vs analytic transcendental to 1e-6 (1D).
- M2 Strip 500 × 220 nm Si/SiO₂ at 1.55 µm: TE0 n_eff = 2.44 ± 0.01, TM0 ≈ 1.78 ± 0.02 at Δ = 20 nm; convergence with Δ documented.
- M3 Cross-check against femwell in a notebook (not CI).
- M4 n_g of the strip ≈ 4.2 ± 0.1.

### 11.4 Integration

- I1 Straight waveguide (3D, Lorentz Si): |S21| ≥ 0.995, |S11| ≤ −40 dB, arg(S21) matches mode-solver β(λ)·L within 3°.
- I2 Directional coupler vs Meep (Linux, conda-forge Meep): identical constant-index materials (n = 3.48 / 1.444), identical Δ, Meep `EigenModeSource` + mode decomposition. |S| within 0.02 absolute and phase within 3° at 21 wavelengths for all four ports. Notebook publishes the comparison table and field plots.
- I3 Coupler vs coupled-mode theory: coupling length from even/odd mode-solver n_eff within 5 % of FDTD.
- I4 2D coupler vs Meep 2D with the same effective indices, same tolerances.
- I5 Ring resonator (v1 SHOULD): resonance wavelengths vs mode-solver n_g and ring length within 0.5 nm; sets up v1.2 harmonic inversion.

### 11.5 Backend parity

- P1 `numpy` vs `torch` CPU: relative L2 field difference < 1e-5 after 100 and 1000 steps on a 2D and a small 3D plan.
- P2 `torch` CPU vs `torch` ROCm: < 1e-4 (reduction order differs).
- P3 S-parameters across backends: |ΔS| < 1e-4 (torch), < 1e-3 (wgpu, v1.1).
- P4 Saved-plan round trip: identical results from a `.npz` plan.

### 11.6 Regression and benchmarks

Golden S-parameter files for I1–I4 stored under `tests/golden/`; any change beyond tolerance fails CI. `bench` tests run manually and append to `benchmarks/results.jsonl`.

## 15. Assumptions and defaults (override in §16 or later)

1. Units: µm, c = ε₀ = μ₀ = 1; wavelengths in µm at the API; frequencies in 1/µm internally.
2. Default cell 20 nm isotropic; Courant 0.99; `AutoGrid` uses 20 steps per wavelength in the highest-index medium.
3. PML 12 cells, m = 3, κ_max = 1, α_max = 0.05, tuned in M3.
4. Port extension 1.5 µm; port margin 1.0 µm; source one cell outside and monitor one cell inside the port plane; z margin 1.0 µm above cladding top and below BOX bottom.
5. Default band 1.5–1.6 µm, 21 points; pulse covers 1.45–1.65 µm.
6. Materials: Si, SiO₂, Si₃N₄, Ge, Air with 1–2 Lorentz poles fitted over 1.2–1.7 µm; constant-index media also available.
7. Default LayerStack: gdsfactory generic SOI 220 nm (`LAYER_STACK`), material names `si`, `sio2`, `sin`, `ge`; substrate Si below a 2 µm BOX if inside the domain.
8. Subpixel averaging: volume fraction, N_ss = 4; PEC dominates.
9. ≤ 2 Lorentz poles per material and per cell.
10. Dispersive ADE arrays restricted to a bounding box (SHOULD in v1).
11. Non-Manhattan ports rejected; OASIS accepted via gdsfactory.
12. fp32 fields; fp64 DFT accumulators optional; mode solver fp64.
13. Results: xarray; Touchstone v1 RI format; sax model via `to_sax()`.
14. Python 3.12, MIT, PyPI name `picfdtd` placeholder.

## Appendix A. Coefficient summary

```
Δt   = S / sqrt(1/Δx² + 1/Δy² + 1/Δz²)                  S = 0.99
ca   = (ε_∞ − σΔt/2) / (ε_∞ + σΔt/2)
cb   =  Δt / (ε_∞ + σΔt/2)
ω_p  = 2π f_p                                            f_p in 1/µm
C1_p = (2 − ω_p²Δt²) / (1 + δ_pΔt)
C2_p = −(1 − δ_pΔt) / (1 + δ_pΔt)
C3_p = Δε_p ω_p² Δt² / (1 + δ_pΔt) · f_m                 f_m: cell volume fraction of the material
b_w  = exp[−(σ_w/κ_w + α_w) Δt]
c_w  = σ_w (b_w − 1) / (σ_w κ_w + κ_w² α_w)
σ_w(ρ) = σ_max (ρ/d)^m ;  κ_w(ρ) = 1 + (κ_max−1)(ρ/d)^m ;  α_w(ρ) = α_max (1−ρ/d)
```

## Appendix B. Functional stepper pseudocode

```python
def step(state: State, p: PlanArrays, n: int) -> State:
    xp = array_namespace(state.Ex)
    # --- H update (t = n+½) ---
    cEx, cEy, cEz = curl_E(state.E, p, xp)              # uses κ-scaled derivatives; PML slabs add ψ_e
    psi_e = update_psi(state.psi_e, dE_terms, p.cpml.b_e, p.cpml.c_e, xp)
    H = tuple(Hi - p.dt * (ci + psi_i) for Hi, ci, psi_i in zip(state.H, (cEx, cEy, cEz), psi_e_terms))
    H = inject_M(H, p.sources, p.g_h[n])
    # --- ADE (P^{n+1} from E^n) ---
    P_new = tuple(pole.C1 * P0 + pole.C2 * P1 + pole.C3 * E_box(state.E, pole.slices)
                  for pole, (P0, P1) in zip(p.ade, state.P))
    dP = sum_over_poles(P_new - P0, xp)                  # scattered back into full-grid shape via slices
    # --- E update (t = n+1) ---
    cHx, cHy, cHz = curl_H(H, p, xp)
    psi_h = update_psi(state.psi_h, dH_terms, p.cpml.b_h, p.cpml.c_h, xp)
    E = tuple(p.ca[i] * state.E[i] + p.cb[i] * (curl_i + psi_i - dP[i] / p.dt) for i, ...)
    E = inject_J(E, p.sources, p.g_e[n])
    # --- monitors ---
    dft = accumulate_dft(state.dft, E, H, p.monitors, n, xp)
    tm  = record_time(state.tm, E, H, p.monitors, n)
    return State(E=E, H=H, P=tuple((Pn, P0) for Pn, (P0, _) in zip(P_new, state.P)), psi_e=psi_e, psi_h=psi_h, dft=dft, tm=tm, n=n + 1)
```

The loop is `for n in range(n_steps): state = step(state, p, n)` in NumPy/PyTorch (optionally `torch.compile(step)`), and `lax.fori_loop` in a future JAX backend.

## Appendix C. WGSL kernel sketch (v1.1)

Storage layout: each field is one `array<f32>` of length nx·ny·nz, index `i + nx*(j + ny*k)`. Workgroup 8×8×4 = 256 invocations.

```wgsl
struct Grid { nx: u32, ny: u32, nz: u32, dt: f32, inv_dx: f32, inv_dy: f32, inv_dz: f32 };
@group(0) @binding(0) var<uniform> g: Grid;
@group(0) @binding(1) var<storage, read>       Ex: array<f32>;
@group(0) @binding(2) var<storage, read>       Ey: array<f32>;
@group(0) @binding(3) var<storage, read>       Ez: array<f32>;
@group(0) @binding(4) var<storage, read_write> Hx: array<f32>;
@group(0) @binding(5) var<storage, read_write> Hy: array<f32>;
@group(0) @binding(6) var<storage, read_write> Hz: array<f32>;

fn idx(i: u32, j: u32, k: u32) -> u32 { return i + g.nx * (j + g.ny * k); }

@compute @workgroup_size(8, 8, 4)
fn update_h(@builtin(global_invocation_id) id: vec3<u32>) {
  let i = id.x; let j = id.y; let k = id.z;
  if (i >= g.nx - 1u || j >= g.ny - 1u || k >= g.nz - 1u) { return; }
  let c = idx(i, j, k);
  let dEz_dy = (Ez[idx(i, j + 1u, k)] - Ez[c]) * g.inv_dy;
  let dEy_dz = (Ey[idx(i, j, k + 1u)] - Ey[c]) * g.inv_dz;
  let dEx_dz = (Ex[idx(i, j, k + 1u)] - Ex[c]) * g.inv_dz;
  let dEz_dx = (Ez[idx(i + 1u, j, k)] - Ez[c]) * g.inv_dx;
  let dEy_dx = (Ey[idx(i + 1u, j, k)] - Ey[c]) * g.inv_dx;
  let dEx_dy = (Ex[idx(i, j + 1u, k)] - Ex[c]) * g.inv_dy;
  Hx[c] = Hx[c] - g.dt * (dEz_dy - dEy_dz);   // PML slabs: multiply derivatives by 1/κ and add ψ (separate kernel or branch on slab index)
  Hy[c] = Hy[c] - g.dt * (dEx_dz - dEz_dx);
  Hz[c] = Hz[c] - g.dt * (dEy_dx - dEx_dy);
}
```

`update_e` is the same shape with `ca`/`cb` buffers, the ADE polarization buffers on their bounding box, and the ψ_h contributions. Host loop (wgpu-py): create pipelines once, encode 64 steps per command buffer (`update_h`, `inject_m`, `update_ade`, `update_e`, `inject_j`, `dft_accumulate`), submit, and read back accumulators through a staging buffer at the end. Request `max_storage_buffer_binding_size` and `max_buffer_size` up to the adapter limits at device creation; grids whose field buffers exceed those limits are rejected with a clear message.

*End of specification.*
